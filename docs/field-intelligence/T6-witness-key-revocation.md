# T6: server-attested witness key revocation

Submission → challenged image → Signed witness statements now includes **Revoke a retained signing key** for the statement owner or a project manager with submission update access. Choose the retained original/change key and record a reason. Read-only viewers see checked status and signed revocation history without write controls.

Revocation is permanent within the project and applies to every retained statement/change using the same public-key fingerprint. New signatures using that key are refused. A statement containing a revoked key no longer counts as active corroboration; correction cannot restore it. The owner may still withdraw it using a fresh key. Original signatures are never rewritten. Revocation does not establish when a key was compromised.

The server uses the existing configured ES256 offline authority (`FIELD_DATA_OFFLINE_SIGNING_KEY`, `FIELD_DATA_OFFLINE_ORIGIN`) to sign a purpose-separated revocation containing project, key fingerprint, authenticated revoker, reference statement, reason, request identity and server timestamp. Missing authority configuration disables the form and fails closed at the API. Existing revocations remain readable/replayable after authority configuration changes. Witness keys are presently self-generated per statement/change; this is **not certified personal identity, delegation, hardware trust or proof of presence**.

The immutable project ledger survives source challenge deletion and migration rollback. Project deletion removes its ledger. Project-level transaction locking serializes witness signing, changes and revocation. Owner/manager authorization is rechecked under grant locks. Exact request retries return the same attestation; conflicting reuse is rejected. Audit entries record key, reference statement, reason code and authority key identifier without copying free-text reasons.

Exports include original signed envelopes and point-in-time key status with signed revocations. `cloudflare/verify-capture-witness.mjs` checks statement/history signatures only. `cloudflare/verify-witness-key-revocation.mjs` separately verifies revocations using `verifyWitnessKeyRevocation(attestation, { publicKey, issuer, projectId, keyHash })`. Obtain `publicKey` and `issuer` through an independently trusted channel; accepting the key supplied in the export alone does not establish trust. Keep historical trusted authority keys when rotating. A clear/absent revocation in an old export is not proof that a key remains unrevoked now. Recheck the authenticated server for current status. Browser signature checking alone cannot establish account identity or claim truth.

Verification covers fingerprints, purpose separation, pinned issuer verification, wrong issuer/scope and tampering, owner/manager boundaries, unavailable signing, idempotency, append-only persistence, source deletion/rollback, blocked key reuse/correction, permitted withdrawal, browser interrupted-request retries, exports, tampered trust metadata and mobile layout. Pilot acceptance remains deferred. All eight programme areas remain partial; certified identity, delegation, certified identity-key revocation and independent sensor/hardware corroboration remain pending.

[T8](T8-reviewed-witness-key-certificates.md) adds second-manager reviewed account/key certificates with explicit assurance methods and expiry. The same permanent project revocation applies to certified keys; independent personal-identity validation is not inferred from a signature.
