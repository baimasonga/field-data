# S6: opt-in value recodes in native CSV ZIP downloads

In the submission download dialog for a published unencrypted form, choose **Download recoded CSV ZIP**. Existing download actions retain stored-answer behavior. The new action uses the existing native CSV ZIP route with `valueRecodes=true&attachments=false`, preserves existing selection/group/deleted-field settings, and forces combined select-multiple values. It remains available for forms with no repeats because the ZIP also carries its rule manifest.

The export applies reviewed active value rules once, according to each submission's stored form version, to eligible root and repeat fields. Multiple-choice values map token by token. Unmapped values, current-version answers and source XML remain unchanged. Moved-question rules, geometry, binary fields and unavailable fields are listed as skipped, never silently applied. Path/value analysis exports retain their existing broader behavior. Native OData and plain root CSV are not recoded by this increment.

The native ZIP includes `field-data-recodes.json`: method, source definition/version and export settings, a deterministic snapshot fingerprint, the full eligible rule mappings/versions/IDs, skipped rules and limitations. These lists describe rule scope, not the number of changed answers. Rules are loaded once before opening export streams; retirement cannot change their in-request snapshot. ETags incorporate the rule/definition/options snapshot, so retirement changes the manifest and response validator. Export filtering is still handled by the existing native metadata-filter implementation before recoding; this does not add answer-field filters. No source submissions or review decisions are written.

The native API supports both CSV ZIP paths (with or without attachments) and GET/POST, requiring existing submission read and additional form read access for rule disclosure. Plain CSV, drafts, encrypted forms and split-select-multiple requests explicitly reject opt-in recoding. Invalid options, malformed/ambiguous active rules or active rules exceeding the existing 200-rule/200-KiB per-form limit fail before opening row streams. Requests without the flag or with `false` keep ordinary export semantics. Recoded responses are private/no-store; existing native audit and download handling remain in place.

Tests cover scalar/token mapping once, version bounds, skipped fields/rules, root/repeat CSV results, manifests, ordinary downloads, filters, full ZIP output, unchanged XML, retired-rule ETags, permissions, unsupported requests, download link options and mobile layout. Native moved-question recodes, OData overlays, approved adaptive policies, conversational collection and field acceptance remain pending. Adaptive surveys and all eight areas remain partial.
