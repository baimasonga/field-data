# Review workload metrics

The claim review queue shows form-scoped workload totals and elapsed times.
`GET /v1/field-data/review-queue/metrics?projectId=1&xmlFormId=survey`
requires the same form-level `submission.read` permission as the queue. An
inaccessible form returns 404; responses are private and must not be cached.

Each response uses one database snapshot and includes:

- `generatedAt`: server observation time.
- `counts`: open, in-review, resolved and superseded cases for the selected form.
- `oldestActiveSeconds`: elapsed time since the oldest open/in-review case opened.
- `averageFirstAssignmentSeconds` and `assignedCaseCount`: time from case opening
  to its first recorded assignment audit event, across cases with an assignment.
  Releasing and reassigning a case does not reset its first assignment time.
- `averageResolutionSeconds`: time from opening to resolution for resolved cases.
- `activeReasons`: active-case counts by routing reason; each case counts once
  per reason and can contribute to multiple reasons.
- `decisions`: counts of append-only decisions and recorded overrides.
- `backchecks`: requested visits on active cases, and those past their due date.
  Linked/cancelled visits and visits on resolved/superseded cases are excluded.

Deleted submissions and other forms are excluded from every aggregate. Empty
counts are zero; timings without observations are null and shown as “No data”.
Metrics refresh when the selected scope or queue changes and after review
mutations. A failed metrics request offers retry independently of the queue.
These are lifetime process metrics, not collector or reviewer rankings.

PostgreSQL acceptance checks authorization, empty data, deleted/form scope,
reason deduplication, assignment/resolution timing and overdue active visits.
Browser acceptance checks rendering, form changes and retry without losing
review actions. The device pilot remains pending; these tests do not establish
offline Collect behavior.
