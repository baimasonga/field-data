# Supervisor field mappings

In **Compare answers**, a supervisor can expand **Configure field mapping**, add
one-to-one original/backcheck field pairs, provide a reason, and save. Each mapping
belongs to that linked pair's pinned submission versions. It is not a reusable
form template. Viewers can inspect mappings and history but cannot change them.

Different forms initially show every answer as **unmapped**, including identical
field names. Same-form comparisons retain exact-path comparison until a mapping
is saved. Once configured, only selected pairs are compared. Other fields remain
independently unmapped. An empty mapping deliberately marks everything unmapped.

Paths are literal names and one-based repeat positions, with encoded namespace
URIs, for example `/people[1]/person[2]/age[1]`. Wildcards, expressions, transforms,
unit conversions and inferred repeat identities are unsupported. Select suggested
paths from the pinned answers. A manually entered path can be absent on one side
if its selected counterpart is present; this displays a missing answer. A pair
absent on both sides is rejected. Empty text remains distinct from missing text.

Saving requires `project.update` on the original project, `submission.update` on
the original form, and `submission.read` on both source forms. Both submissions
must remain undeleted and source hashes must verify. No mapping change modifies
case revision, review status or decisions, or generates an automatic outcome.

`POST /v1/field-data/review-queue/:caseId/backchecks/:backcheckId/mapping` accepts
`{ requestId, note, pairs: [{ originalPath, backcheckPath, label }] }`. Use the
comparison response's `mapping.etag` as `If-Match` (`"backcheck-mapping-0"` initially).
A missing header returns 428; a stale revision returns 412. Reload and review the
latest mapping before submitting a new change. Retry the same request UUID and
payload after an uncertain response: it returns the original revision without
appending another record. Changing the payload for a used UUID is rejected.

Maps are bounded to 100 pairs and 64 KiB serialized data. Labels are at most 100
characters and a nonblank reason is required (at most 2,000 characters). Existing
XML and comparison row limits apply. The comparison uses `backcheck-mapped-text@1`
for explicit mappings or independent unmapped fields. Unverified sources expose
no answer rows or suggested paths and cannot receive new mappings.

Each save appends a revision with actor, timestamp, reason, pairs, source definition
IDs and source hashes, alongside a transactional `field_data.backcheck.mapping`
audit. The comparison displays the latest 100 revisions; older records remain in
the database. Requests are serialized on the linked backcheck row and use their
own revision checks, independently of review writes.

Deploy migration `20261009-03-add-backcheck-field-mappings.js` before the API and
client. Rolling it back retains recorded mapping evidence. An empty mapping table
can be removed so earlier empty feature tables can also roll back. Reapply accepts
retained tables. Parser, API and browser regressions cover mapped/missing/unmapped
answers, role boundaries, retries, conflicts, history and mobile wrapping. Fresh
public/custom-schema migration probes check rollback/reapply retention.
