# K8: recorded location comparisons for possible duplicate assets

**Possible duplicate assets → Location fact name → Compare recorded locations** lets readable users explicitly compare the two assets' latest applicable facts for an exact predicate. The default name is `location`; it is only a starting input, not a special inferred field. Register a cited asset observation with that fact name and a value in ODK geopoint form (`latitude longitude [altitude [reported accuracy]]`) through the existing passport. No device location or submission field is inferred automatically.

The read-only comparison shows spherical straight-line separation, each selected observation's source claim, valid-from and recorded times, freshness and usability status. If both facts report accuracy, it also shows distance minus/plus the sum of their reported radii (minimum floored at zero). These are device estimates, not confidence bounds. Missing accuracy withholds that range, not the raw separation. Altitude is ignored. Nearness does not prove the same asset, and separation does not prove different assets; facts may refer to different visit times/reference points or legitimate asset movement. Existing candidate generation, dismissal and manual merge rules are unchanged.

Selection uses existing current observation ownership and temporal ordering: latest valid-from, then recorded time/sequence, with future facts excluded. A latest unknown/not-observed/not-applicable, expired, review-due, source-unverified or malformed fact withholds distance rather than falling back to an earlier known point. The accepted format has two to four finite decimal numbers, ordinary latitude/longitude bounds, excludes 0,0 as a no-fix placeholder, and allows reported accuracy from 0 to 100,000 metres. Arbitrary text and geotraces are not interpreted.

`GET /field-data/projects/:projectId/assets/:assetId/location-comparison/:otherAssetId?predicate=...` requires project read, both active assets' form read access and read access to every evidence source currently owned by either asset, matching the passport's existing history policy. A source-deleted form/submission or history beyond the existing 500-observation bound fails closed. Source integrity is recomputed with the retained claim XML and provenance hash; bytes verifying does not verify the physical location claim. Query/IDs are bounded and responses private/no-store. Comparison performs no writes and does not require project management. Missing access clears the browser result; changing the predicate clears stale results; requests run only on explicit submission.

Tests cover distance arithmetic, reported-radius ranges/missing accuracy, invalid/no-fix coordinates, unknown/expired/future/unverified facts, latest replacement behavior, citations, source grants and revocation, input limits, read-only controls, retry, stale-result clearing and mobile layout. This is a bounded recorded-fact comparison, not asset maps, photo identity matching, automatic duplicate generation from proximity or validated identity inference. Knowledge and all eight areas remain partial; device/pilot acceptance remains separate.
