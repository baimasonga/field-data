# Dedicated backcheck forms

The assigned reviewer can select an existing published, open form in the same
project for a backcheck. Create and publish that form through Central, then
assign the intended App Users to it. The request does not create a form or grant
permissions. Collect downloads and submits it through the existing OpenRosa
workflow, including offline collection. [The companion inbox and browser notifications](P0.6-app-user-notifications.md)
provide assignment delivery; live push requires deployment configuration and browser consent.

`GET /v1/field-data/review-queue/:caseId/backcheck-forms` returns response forms
readable by the reviewer and their eligible project App Users. The UI resets the
collector choice when the form changes. The server independently validates the
form, permissions, collector assignment and independence from the original
submitter. `responseXmlFormId` is optional on request creation; omission uses the
original form and preserves legacy retry hashes. Explicit form selection is part
of the immutable request and retry hash.

Linking requires a synced, undeleted, published submission from the selected
collector and response form. A same instance ID in a different form cannot
change the target. Reviewers must have submission read permission on both forms
to list requests or inspect comparisons; linking additionally requires the
existing update permission on the original case. Denied reads return 404.

Linked source versions remain pinned. UI submission links and exact XML downloads
use the response form. Comparisons display each source form and warn that matching
paths across different forms do not imply equivalent questions or answers. No
field mapping, automatic verdict, or semantic equivalence is inferred.

Migration `20261009-01-add-backcheck-response-form` adds a restrictive form foreign
key and backfills existing requests from their original claim. Rollback retains
the column and selected form; reapply preserves explicit selections and backfills
legacy NULL inserts. An older application cannot link dedicated-form requests:
upgrade again to continue these requests, or cancel them before application
rollback. Keep request history and audit rows.

Validation covers dedicated-only collector access, wrong-form rejection, retry
identity, form-level read permissions, pinned XML links, browser selection and
collector reset, plus PostgreSQL rollback/reapply and legacy backfill.
