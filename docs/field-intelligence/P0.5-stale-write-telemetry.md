# Stale-write conflict telemetry

The workload panel reports form-scoped lifetime counts of authorized review writes
rejected with `412.1` because their `If-Match` revision was outdated. Expand
**Stale write conflicts** to see assignment, release, decision and backcheck
request/cancel/link totals. Refreshing the queue after a failed mutation also
refreshes these totals. The count describes workflow friction, not staff performance.

Only a validated, authorized write that reaches the locked revision check is
observed. Missing/malformed revisions, permission denials, assignment conflicts,
closed cases and idempotency mismatches are excluded. Successful retries replay
before the revision check and are excluded. A rejected request repeated with the
same key is another rejected attempt and counts again. Historical 412s predating
this deployment cannot be reconstructed and are not backfilled.

A resource failure observer runs after the endpoint's transaction has rolled back
and before its error response is sent. It appends a diagnostic core audit with
action `field_data.review.case.stale_write`, the authenticated actor, owning form
actee and only `{caseId, operation}` in its details. It stores no request body,
notes, idempotency key or expected/current revisions. This diagnostic event is
separate from human decision history and does not change case revision, evidence,
assignment or mutation replay records. It needs no new schema migration.

Observation storage is best effort. A storage failure emits a fixed server log
message and preserves the original 412 response. Counts may therefore understate
failures during an outage; they also follow core audit retention. Form read
permission gates totals, and deleted submissions and other forms are excluded.
Aggregates expose no actor ranking. The metrics response remains private/no-store.

Regression coverage uses real request transactions to prove the failed mutation
rolls back while the diagnostic event persists, covers all six operations, repeated
rejections, successful replays, excluded errors and deleted/form scope. Unit tests
check observer ordering and storage failure handling; a browser fixture checks
revision refresh, safe retry and scope-specific totals. Offline Collect validation
still belongs to the device pilot.

Rollback reverts application code. Existing diagnostic audits can remain; do not
remove human decisions or source records to roll back telemetry.
