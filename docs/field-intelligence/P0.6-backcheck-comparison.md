# Original/backcheck answer comparison

The evidence panel offers **Compare answers** for a linked backcheck. It loads
on request, independently of review actions, and shows original and backcheck
text side by side with same, changed, missing-from-original and
missing-from-backcheck labels. An empty element is **Empty answer**; an absent
field is **Not present**. Text is rendered as text, with an accessible table and
mobile wrapping. A failed load offers a separate retry.

`GET /v1/field-data/review-queue/:caseId/backchecks/:backcheckId/comparison`
requires owning-form `submission.read`. It fetches the case's exact claim version
and the linked `responseSubmissionDefId` in one database snapshot. Both submissions
must be undeleted and belong to the same form, and the backcheck must be linked
to the requested case. Unavailable/deleted/inaccessible pairs return 404. The
response is private/no-store; no decisions, case revisions or audit records are
changed by comparison.

Each source includes its submission/claim version identifier, instance/root ID,
form version, current-version marker, provenance, integrity status and a download
link for that exact XML version. Editing a response later does not silently
replace the linked version. Historical-version and degraded-provenance markers
remain visible. Stored SHA-256 provenance hashes are checked against the exact XML;
unverified or mismatched sources return `unavailableReason: source-integrity`
with source metadata and no answer rows.

The `backcheck-text@1` algorithm compares decoded XML leaf text without trimming
or numeric/date/unit conversions. It excludes root metadata, field attributes
and attachment contents; an attachment filename is only text. Namespace URIs
are escaped and preserved in field paths and equivalent prefixes match. Sibling elements
are indexed from one, including nested repeats. Repeats align by position, never
by inferred identity: insertion/reordering may appear as changed/missing fields.
Different form versions may change field meaning; the UI makes that limitation
visible. This comparison provides no score, recommendation or automatic verdict.

Strict XML parsing rejects malformed documents, DTDs and mixed-content answer
groups (`unsupported-xml`) without resolving external content. Each source is
limited to 2 MiB; parsing limits depth to 64 and nodes to 20,000. At most 5,000
answer rows, 8 KiB per field path, and 2 MiB of serialized row data are returned. Limit failures return
`size-limit` with source metadata and no partial comparison. Reviewers can inspect
the source versions instead.

Regression coverage checks changed and pinned historical answers, form read
permissions, source integrity, deleted sources and unchanged case/decision state.
Parser tests cover missing/empty values, namespaces, nested repeats, malformed
XML, DTDs and resource limits. Browser fixtures cover safe text rendering, missing
values, historical/degraded warnings, independent retry and mobile reflow.

No schema migration is needed. Deploy the API and client together; rollback reverts
application code and retains source submissions, links, decisions and audits.
The device pilot and push notifications/dedicated backcheck forms remain separate.
