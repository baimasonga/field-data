# P0.1 — Provenance envelope

The first work package of Phase 0. Both agents build against this file; neither
invents its own shape. Changes here are agreed before either implementation
moves.

## The decision this improves

A reviewer looking at a Submission cannot currently tell where its values came
from. A row imported from a CSV is indistinguishable from one collected on a
phone in a village, except to somebody who knows to read the audit log. Once a
reviewer can answer *where did this come from*, every later capability in the
suite — evidence links, verification, confidence, review — has something to
attach to.

## What exists today

`submission_defs` already carries a little of this and it is worth being exact
about what, because the envelope must not duplicate it:

| Column | Meaning |
| --- | --- |
| `instanceId` | Client-generated identifier; ODK dedupes on it |
| `submitterId` | The actor the server authenticated |
| `deviceId` | Reported by the client, unverified |
| `userAgent` | Reported by the client, unverified |
| `createdAt` | Receipt time at the server |

Nothing records capture time as distinct from receipt time, how the row
arrived, what produced it, or whether the bytes are still the bytes.

## Design decision: a separate table

The envelope goes in a new `field_data_submission_provenance` table keyed on
`submissionDefId`, not as columns on `submission_defs`.

This repository is a fork of ODK Central and will keep merging upstream.
Columns added to core tables turn every future upstream migration into a
conflict; a separate table owned by the fork does not. The cost is a join. The
existing fork tables (`field_data_webhooks`, `field_data_filtered_datasets`)
already follow this convention.

## Schema

```
field_data_submission_provenance
  submissionDefId   integer  primary key, references submission_defs(id) on delete cascade
  origin            text     not null, check in ('collected','imported','migrated','api')
  sourceRef         text     null      -- import batch id, migration name, integration name
  capturedAt        timestamptz null    -- when the observation was made, if known
  receivedAt        timestamptz not null default clock_timestamp()
  integrityHash     text     not null   -- sha256 of the submission xml, lowercase hex
  transformVersion  text     not null   -- what produced this row, e.g. 'csv-import@1'
  policyVersion     text     not null   -- the provenance policy applied, e.g. 'p0.1'
  degraded          jsonb    null       -- explicit record of what was unavailable
```

Notes that matter:

- **`capturedAt` is nullable and that is the point.** A CSV import does not know
  when the observation happened. Recording null is honest; defaulting it to the
  receipt time would manufacture a fact.
- **`degraded`** carries the suite's requirement that unavailability is recorded
  explicitly rather than inferred from absence. Shape: `{"capturedAt":"unknown"}`.
- **`origin` is closed.** A new origin needs a migration, which is the point: it
  is a small, auditable vocabulary, not free text.
- **No `deletedAt`.** Provenance is immutable. It is written once with its
  Submission version and never updated; a correction creates a new version with
  its own row.

## Backfill

Every existing `submission_defs` row gets `origin='collected'`,
`transformVersion='backfill@1'`, `policyVersion='p0.1'`,
`receivedAt = submission_defs."createdAt"`, `capturedAt = null`,
`degraded = '{"capturedAt":"unknown","origin":"assumed"}'`.

`origin='collected'` is an assumption — the rows predate the envelope — and the
`degraded` marker says so rather than presenting the assumption as knowledge.
Do not claim an integrity hash was verified at capture; compute it at backfill
and mark it in `transformVersion`.

## API

Provenance rides with a Submission version, never as a separate lookup a caller
can forget:

```
GET /v1/projects/:projectId/forms/:xmlFormId/submissions/:instanceId
  ... existing body ...
  "provenance": {
    "origin": "imported",
    "sourceRef": "csv-import:8f2a…",
    "capturedAt": null,
    "receivedAt": "2026-09-22T21:31:04.000Z",
    "integrityHash": "9c1b…",
    "transformVersion": "csv-import@1",
    "policyVersion": "p0.1",
    "degraded": { "capturedAt": "unknown" }
  }
```

A version with no provenance row returns `"provenance": null` rather than a
fabricated default. That can only happen for rows written between the migration
and the write path landing, and a null says so.

## Error cases

| Case | Behaviour |
| --- | --- |
| Write path omits provenance | Reject the write. Provenance is not optional for new rows. |
| Unknown `origin` | 400 naming the allowed values. |
| `capturedAt` in the future beyond clock skew | Accept, and record `degraded.capturedAt = "implausible"`. Do not silently correct. |
| Hash mismatch on read | Return the row with `integrityStatus: "mismatch"`. Never hide it. |
| Backfill meets a row whose xml is unreadable | Record the row, mark `degraded.integrityHash = "unreadable"`. |

## Division of work

**ChatGPT / Codex**

1. `central/server/lib/util/provenance.js` — pure functions only:
   - `canonicalHash(xml)` → lowercase hex sha256 over the exact bytes stored.
   - `buildEnvelope({ origin, sourceRef, capturedAt, xml, transformVersion })` →
     the record above, including `degraded` derivation.
   - `validateEnvelope(envelope)` → throws with the error cases in this file.
2. `central/server/test/unit/util/provenance.js` — unit tests: every error case,
   a null `capturedAt`, an implausible `capturedAt`, a hash over non-ASCII XML.
3. A migration draft at `central/server/lib/model/migrations/` following the
   fork's naming, with `up` and a real `down`.

`lib/resources/field-data.js`.

## Done when

- A Submission collected through the API and one created by CSV import are
  distinguishable through the API, by origin, without reading the audit log.
- Every existing row has provenance, with its assumptions marked.
- An integration test proves both paths through the real routes.
- `down` reverses the migration on a database with rows in it.
- The client gate and both server gates pass.

Not done when the table exists but nothing writes to it.
