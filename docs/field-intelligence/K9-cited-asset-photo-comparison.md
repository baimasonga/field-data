# K9: cited retained-photo comparison for possible duplicate assets

**Possible duplicate assets → Photo fact name → Compare referenced photos** loads a pair of cited retained images only after an explicit request. Record a current asset fact (default predicate `photo`) whose value is the exact attachment filename in that fact's cited submission version. Reviewers may choose another predicate. A filename is resolved only in its own cited claim; no URL, other source or older fact is substituted.

The read-only endpoint selects current observation ownership and existing temporal fact ordering. Latest unknown, stale, malformed or source-unverified facts withhold that side. Both active assets and all their currently owned evidence sources must be readable, following passport policy; source/form deletion, lost access and oversized history fail closed. Fact-source XML integrity is checked using existing provenance. This verifies retained source bytes, not the physical location, capture time or truth of a photo.

The endpoint returns PNG/JPEG attachment bytes up to 5 MiB per side, SHA-256 fingerprints and observation/source citations with valid-from, recorded and check times. MIME/header checks reject unsupported files; the browser verifies each byte count and fingerprint before creating local preview URLs and handles image decoding failures. No external provider is called. Temporary URLs and displayed results are cleared after input changes, failed refresh/access checks and unmount. File equality is recomputed from verified fingerprints in the browser, without trusting an asserted identity decision.

The comparison names whether the retained files have identical or different bytes, or whether comparison is unavailable. Identical files may have been reused; different files may depict the same asset. There is no image-content similarity model, identity score, automated merge or new duplicate generation. Capture time/presence are not established. The images are a snapshot of attachments retained at the check time: attachment replacement can change a subsequent comparison, and the cited XML's integrity does not certify the original attachment bytes. Existing capture-challenge/witness history is separate. Comparisons are transient and do not retain a new immutable evidence record.

`GET /field-data/projects/:projectId/assets/:assetId/photo-comparison/:otherAssetId?predicate=...` is private/no-store, validates both IDs and the bounded exact predicate, and performs no asset writes. Readable users do not need project-management rights. Source permissions are rechecked on every request; already viewed or downloaded bytes cannot be recalled by later permission revocation.

Tests cover bounded names, URL/path rejection, latest replacement semantics, stale/unknown/future/unverified references, exact bytes and citations, attachment replacement, unsupported and missing files, independent source grants/revocation, tampered response hashes, browser equality labels, retry/error clearing, local previews and mobile layout. Image-content identity inference, broader image types, photo field acceptance and asset maps remain pending. Knowledge and all eight programme areas remain partial.
